# Building and testing

Kiki is a Rust project. With a stable Rust toolchain and its
`wasm32-unknown-unknown` target:

```bash
rustup target add wasm32-unknown-unknown
cargo build                 # debug build, in target/debug/kiki
cargo build --release       # release build, in target/release/kiki
cargo test
cargo fmt
cargo clippy --all-targets --all-features -- -D warnings
```

The repository is also a Nix flake, which is what CI builds. `nix develop`
gives a shell with the toolchain and everything below, and each CI job is one
of the flake's checks:

```bash
nix build .#checks.x86_64-linux.tests     # or fmt, clippy, book
nix flake check                           # all of them
```

Default plugins written in Rust, such as the [filter](plugins/filter.md),
keep their source in `plugins/<name>-src`, a crate named `kiki-<name>` in
the Cargo workspace in `plugins/`, and their `plugin.wasm` isn't kept in the
repository: `build.rs` builds the workspace whenever it or the SDK in
`sdk/rust/kiki-plugin` changes, and bundles each as `<name>/plugin.wasm`. To
port another default plugin, add its crate to the workspace's `members`. To
bundle prebuilt plugins instead, set `KIKI_PLUGINS_WASM_DIR` to a directory
holding them as `<name>.wasm`, as the Nix build does
(`nix build .#wasm-plugins` builds that directory).

## Reports

CI publishes these for the `main` branch on every push:

- **[Test coverage](../coverage/)**, measured with `cargo llvm-cov` over the
  whole test suite (`nix build .#coverage` builds it locally).
- **[Rust API documentation](../docs/kiki_rss/)** for the `kiki_rss` crate,
  including notes on the internals such as
  [memory usage](../docs/kiki_rss/docs/memory/index.html)
  (`nix build .#docs`, or `cargo doc --open`).
- **[HTTP API reference](../api/)**, generated by `kiki docs`.

## This guide

This guide is an [mdBook](https://rust-lang.github.io/mdBook/) in `book/`,
and the landing page in front of it is `book/landing/`. To preview the guide
as you edit it:

```bash
nix develop
mdbook serve book --open
```

`nix build .#book` builds the guide and the landing page together, as they
are published, and checks every link between them.

## Benchmarks and stress tests

`tools/` holds standalone tools with their own Cargo projects:

- [`tools/stress`](https://github.com/kernelmethod/kiki-rss/tree/main/tools/stress)
  drives a running server with concurrent load, to find slowdowns and
  deadlocks.
- [`tools/ipcbench`](https://github.com/kernelmethod/kiki-rss/tree/main/tools/ipcbench)
  measures what Kiki's inter-process traffic costs while it ingests feeds.

For profiling, `cargo build --profile profiling` builds a release binary
that keeps its symbols, so `perf` and flamegraphs can name Kiki's functions.
